## 二、项目背景（约1-2分钟）

### 问题痛点

在日常校园生活中，宿舍设施出现问题是很常见的，比如：
- 水龙头漏水
- 门窗损坏
- 网络故障
- 家具老化

**传统的报修方式存在以下问题：**
1. 需要到宿管处填写纸质表格，流程繁琐
2. 无法实时查看维修进度，学生不知道什么时候能修好
3. 维修完成后缺乏反馈机制，服务质量难以保证
4. 管理人员统计工作量困难，数据分散

### 解决方案

针对这些问题，我们开发了 **DormFix 系统**，实现：
- ✅ 在线提交报修申请
- ✅ 实时查看维修进度
- ✅ 维修完成后在线评价
- ✅ 管理人员数据统计

## 三、功能演示（约5-7分钟）

现在，让我来演示系统的主要功能。

### 1. 用户登录

首先，我们打开系统首页，可以看到登录页面。

系统支持三种角色：
- **学生** - 提交报修、查看进度、评价服务
- **管理员** - 审核报修、派发任务、管理用户
- **维修人员** - 接收任务、更新状态

我先用学生账号登录：`student001` / `123456`

### 2. 学生端功能

**（1）提交报修**

点击"发起报修"按钮，可以看到：
- 选择宿舍楼和房间（支持级联选择）
- 选择报修类别：水电、门窗、网络、家具、其他
- 填写故障描述
- 上传故障照片（可选）
- 选择紧急程度：普通/紧急

**（2）查看工单列表**

提交后，在"我的工单"页面可以看到：
- 工单编号
- 当前状态（待审核、处理中、已完成等）
- 提交时间
- 可以查看详情或撤销工单

**（3）进度时间线**

点击工单详情，可以看到完整的处理流程：
```
提交报修 → 管理员审核 → 派发任务 → 维修人员接单 → 维修完成 → 学生确认 → 评价
```

每个环节都有时间记录，一目了然。

**（4）服务评价**

维修完成后，学生可以对服务进行评价：
- 维修速度评分（1-5星）
- 服务态度评分（1-5星）
- 维修质量评分（1-5星）
- 文字评价（可选）

如果有不满意的地方，还可以提交投诉。

### 3. 管理员端功能

现在切换到管理员账号：`admin` / `admin123456`

**（1）审核派单**

在"待处理"页面，可以看到学生提交的报修申请：
- 查看报修详情
- 选择驳回或派单
- 派单时选择维修人员

**（2）用户管理**

管理员可以管理系统用户：
- 查看所有用户列表
- 新增用户
- 编辑用户信息
- 重置密码
- 启用/禁用账号

**（3）数据统计**

在"数据统计"页面，可以看到：
- 报修数量趋势图
- 各类别报修占比
- 维修人员工作量统计
- 平均处理时长
- 支持导出Excel报表

### 4. 维修人员端功能

最后看一下维修人员账号：`maintainer001` / `123456`

**（1）接单看板**

维修人员可以看到：
- 待接单的任务列表
- 进行中的任务
- 已完成的历史记录

**（2）更新状态**

接单后可以：
- 更新维修进度
- 维修完成后标记为"已完成"
- 等待学生确认

## 四、技术实现（约2-3分钟）

### 技术架构

```
┌─────────────────────────────────────────────┐
│                   前端                        │
│   Django Template + Tailwind CSS + ECharts   │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│                   后端                        │
│        Django 4.2 + Django REST Framework    │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│                 数据库                        │
│          SQLite (开发) / MySQL (部署)         │
└─────────────────────────────────────────────┘
```

### 核心技术点

**1. 后端**
- **Django REST Framework** - 提供RESTful API
- **Token认证** - 无状态的用户认证
- **权限控制** - 不同角色不同权限
- **数据验证** - 完善的参数校验

**2. 前端**
- **Tailwind CSS** - 响应式UI设计
- **ECharts** - 数据可视化图表
- **Fetch API** - 异步请求处理

**3. 数据库**
- **自定义用户模型** - 继承AbstractUser
- **外键关联** - 用户、工单、评价等表关联
- **状态机** - 工单状态流转管理

### 项目结构

```
software_engineering/
├── src/dormfix/
│   ├── accounts/      # 用户管理
│   ├── repairs/       # 报修管理
│   ├── dispatch/      # 派单管理
│   ├── maintenance/   # 维修处理
│   ├── feedback/      # 评价投诉
│   ├── dashboard/     # 数据统计
│   └── templates/     # 前端页面
├── tests/             # 单元测试
└── docs/              # 项目文档
```

## 附录：常见问题准备

**Q: 为什么选择Django而不是其他框架？**
A: Django自带ORM、Admin后台、用户认证等功能，开发效率高，适合快速开发。

**Q: 如何保证数据安全？**
A: 使用Token认证、权限控制、参数校验等机制保证安全。

**Q: 如果要部署到生产环境需要做什么？**
A: 切换到MySQL数据库、配置Nginx反向代理、关闭DEBUG模式、配置HTTPS等。

**Q: 项目有什么不足之处？**
A: 目前没有消息通知功能，后续可以添加短信或邮件通知；还可以增加数据分析功能。
